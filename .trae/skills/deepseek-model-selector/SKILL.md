# DeepSeek 模型选择器

## 概述

当前环境有两个可用模型：**DeepSeek V4 Flash**（默认）和 **DeepSeek V4 Pro**（高复杂度专用）。当用户提出一个新的需求时，本 Skill 负责评估任务复杂度，决定是否建议切换至 Pro 模型。

## 使用方式

在收到用户的新需求后，**首先**根据以下分类标准判断任务复杂度，然后按对应流程处理。

## 分类标准

### ✅ DeepSeek V4 Flash（默认）

以下类型的任务默认使用 Flash 即可，**无需询问用户**：

| 类别 | 示例 |
|------|------|
| 简单代码生成 | 单文件 CRUD、简单脚本、工具函数 |
| 基础 Bug 修复 | 单个文件的错误修复，不涉及跨模块追溯 |
| 简单文件编辑 | 修改几个字段、调整样式、重命名变量 |
| 基础数据查询/分析 | SELECT 查询、简单统计、CSV 转格式 |
| 日常 Git 操作 | commit、push、创建分支、合并简单 PR |
| 简单文档创建 | 短篇说明、README、简单 Markdown |
| 快速信息查找 | 查术语含义、查 API 签名、搜索代码 |
| 简单重构 | 重命名、提取函数（不改变整体架构） |
| 常规运维命令 | 查看日志、重启服务、检查状态 |

### 🔶 DeepSeek V4 Pro（需要提示用户）

以下类型的任务**复杂度较高**，应当提示用户考虑切换到 Pro：

| 类别 | 示例 |
|------|------|
| 多步骤、多文件实现 | 涉及 3+ 个文件的系统性改动，如新增完整模块 |
| 复杂架构设计 | 系统分层、模块拆分、接口契约设计 |
| 安全敏感代码 | 认证/授权、加密、输入校验、防注入 |
| 性能优化 | 查询优化、缓存策略、减少 N+1、内存调优 |
| 跨系统排错 | 涉及前后端/数据库/网络的复杂问题追踪 |
| 大型文档/报告 | 长篇专业文档、PPT、复杂 Excel 报表 |
| 深度领域推理 | 法律、财务、医学等需要专业知识的分析 |
| 复杂数据处理管道 | ETL、多步数据清洗、跨源数据聚合 |
| 系统集成 | 对接多个外部 API/服务，处理数据映射和异常 |
| 需前期调研的任务 | 先搜索研究大量资料再做实现的复杂任务 |
| AI 生成图像/媒体 | 涉及 GenerateImage 等创作型任务 |

## 判断流程

```
用户提出需求
    │
    ├── 明显属于 Flash 类别 → 直接执行，无需提示
    │
    ├── 明显属于 Pro 类别 → 提示用户，等待确认
    │
    └── 不确定 / 介于两者之间
          → 使用以下规则判断：
            - 如果改动涉及 3+ 文件 → 建议 Pro
            - 如果任务需要 3+ 步骤 → 建议 Pro
            - 如果任务涉及不熟悉的技术栈 → 建议 Pro
            - 如果用户要求"高质量/深度"输出 → 建议 Pro
            - 如果任务有高风险（生产环境、数据安全）→ 建议 Pro
            - 其余情况 → 默认 Flash
```

## 提示用户的话术

当判断需要 Pro 时，在响应的**第一句**插入以下模板：

```
🤔 **这个任务比较复杂**（简述原因），建议切换为 **DeepSeek V4 Pro** 以获得更高质量的结果。直接用 Flash 继续，还是换 Pro？
```

如果用户选择继续用 Flash，则正常执行；如果选择 Pro，则**停止当前工作**（用户需手动切换模型后重新发送需求）。

## 示例对话

### 示例 1：简单任务 → 默认 Flash

> 用户：帮我把这个函数加个类型注解
> Agent：直接执行（无需提示）

### 示例 3：边界情况 → 判断后决定

> 用户：分析这份 5000 行的数据并生成可视化报告
> Agent：🤔 **这个任务比较复杂**（涉及大量数据处理和报告生成），建议切换为 **DeepSeek V4 Pro** 以获得更高质量的结果。直接用 Flash 继续，还是换 Pro？
