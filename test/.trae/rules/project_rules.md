## B.9 上下文感知（测试补充）

- Agent 在编写测试前，必须先使用 SearchCodebase 或相关搜索工具获取被测试项目的上下文
- 了解被测试项目的 API 文档、交互设计文档后再编写测试用例
- 修改测试代码前，先阅读同目录下已有测试文件，理解现有测试风格和约定
- 每次任务开始前必须加载以下锚点文档：
  1. [project.md](../../project.md) — 项目背景、当前阶段、测试范围
  2. [本文件](project_rules.md) — 测试 Part B 扩展

## B.10 修改验证（测试补充）

- 每次测试代码修改完成后，必须运行对应测试框架验证测试通过
- 确保测试代码本身语法正确、无类型错误

## B.11 依赖管理（测试补充）

- 使用测试相关依赖前，先检查 `package.json`、`requirements.txt`、`pyproject.toml` 等文件中是否已有替代方案

## B.12 安全红线（测试补充）

- 测试数据必须使用模拟数据，禁止使用生产环境真实数据
- 测试脚本不得对生产环境发起请求或操作

## B.13 测试编写规范

- 每个测试用例必须包含：测试目的、前置条件、测试步骤、预期结果
- 测试必须覆盖正常路径、边界条件和异常场景
- Bug 修复验证必须先编写复现步骤，确认可复现后再验证修复
- 测试用例标题和描述必须清晰可读，便于人工审查
- 自动化测试脚本应遵循 Page Object 模式（Playwright）或对应的测试设计模式

## B.14 Bug 上报规范

- 所有 Bug 必须通过 BugPack MCP 服务上报和管理
- Bug 描述必须包含：复现步骤、实际结果、预期结果、截图/日志
- Bug 分类清晰（前端/后端/接口/UI/逻辑），便于后续追踪
- Bug 状态流转必须及时更新（pending → annotating → generated → fixed → closed）
