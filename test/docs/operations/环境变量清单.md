## 1. 概述

### 1.1 配置加载机制

```
① 系统环境变量（最高优先级，Docker Compose / 生产环境注入）
② .env 文件（开发环境使用，不上传到 Git）
③ Settings 类中的默认值（最低优先级，仅开发调试用）
```

**加载顺序说明**：各服务在 `main.py` 启动入口调用 `shared.config.load_env()` 加载 `.env` 文件，然后由 Pydantic `BaseSettings` 类读取，系统环境变量优先级高于 `.env` 文件。

### 1.2 使用约定

| 约定 | 说明 |
|------|------|
| **命名风格** | `SCREAMING_SNAKE_CASE` |
| **敏感信息** | 密码、密钥、Token 等敏感信息**不允许**提交到 Git |
| **默认值** | 开发环境友好的默认值，生产环境**必须**覆盖 |
| **类型校验** | 由各服务 `config.py` 中 Pydantic Settings 类的字段类型声明负责 |

### 1.3 配置组合说明

部分环境变量由 `shared/config.py` 的工具函数**自动组合**，无需在 `.env` 中直接设置：

| 组合变量 | 组合逻辑 | 依赖的原始变量 |
|---------|---------|--------------|
| `DATABASE_URL` | `postgresql+asyncpg://{DB_USER}:{DB_PASSWORD}@{DB_HOST}:{DB_PORT}/{DB_NAME}?options=-c%20search_path={schema}` | DB_USER, DB_PASSWORD, DB_HOST, DB_PORT, DB_NAME |
| `REDIS_URL` | `redis://[:REDIS_PASSWORD]@{REDIS_HOST}:{REDIS_PORT}` | REDIS_HOST, REDIS_PORT, REDIS_PASSWORD |

## 2. 全局环境变量（三服务通用）

### 2.1 PostgreSQL 连接

用于组合 `DATABASE_URL`，三服务共享同一实例，通过 `search_path` 参数自动追加对应 Schema。

| 变量名 | 类型 | 默认值 | 必需 | 使用服务 | 说明 |
|--------|:----:|:-----:|:----:|:--------|------|
| `DB_USER` | string | `postgres` | ✅ | 三服务 | 数据库用户名 |
| `DB_PASSWORD` | string | `postgres` | ✅ | 三服务 | 数据库密码 |
| `DB_HOST` | string | `postgres` | ❌ | 三服务 | Docker Compose 内为 `postgres`；本地开发改为 `localhost` |
| `DB_PORT` | int | `5432` | ❌ | 三服务 | PostgreSQL 端口 |
| `DB_NAME` | string | `codesail` | ❌ | 三服务 | 数据库名称 |

> **安全提示**：生产环境 `DB_PASSWORD` 必须使用强随机密码，长度 ≥ 16 位，包含大小写字母和特殊字符。

### 2.2 Redis 连接

用于组合 `REDIS_URL`。

| 变量名 | 类型 | 默认值 | 必需 | 使用服务 | 说明 |
|--------|:----:|:-----:|:----:|:--------|------|
| `REDIS_HOST` | string | `redis` | ❌ | 三服务 | Docker Compose 内为 `redis`；本地开发改为 `localhost` |
| `REDIS_PORT` | int | `6379` | ❌ | 三服务 | Redis 端口 |
| `REDIS_PASSWORD` | string | `(空)` | ❌ | 三服务 | Redis 密码。Docker 内部可不设密码；生产环境建议设置 |

## 3. Auth 服务环境变量

### 3.1 JWT 配置

| 变量名 | 类型 | 默认值 | 必需 | 说明 |
|--------|:----:|:-----:|:----:|------|
| `JWT_SECRET` | string | *(无默认值)* | ✅ | JWT 签名密钥。生产环境**必须**使用强随机字符串（推荐 `openssl rand -hex 64`） |
| `JWT_ALGORITHM` | string | `HS256` | ❌ | JWT 签名算法。固定为 `HS256`，不建议修改 |
| `JWT_ACCESS_EXPIRE` | int | `86400` | ❌ | Access Token 有效期（秒）。默认 24 小时。范围：3600~604800 |
| `JWT_REFRESH_EXPIRE` | int | `604800` | ❌ | Refresh Token 有效期（秒）。默认 7 天。范围：86400~2592000 |

> **安全提示**：
> - 开发环境 JWT_SECRET 可使用固定值 `dev-secret-change-in-production`
> - 生产环境**必须**更改，且**不应**提交到 Git
> - Core 服务仅使用 JWT_SECRET 进行验签，不签发 Token

### 3.2 管理员预设

| 变量名 | 类型 | 默认值 | 必需 | 说明 |
|--------|:----:|:-----:|:----:|------|
| `ADMIN_USERNAME` | string | `admin` | ❌ | 预设管理员用户名。最长 50 字符 |
| `ADMIN_PASSWORD_HASH` | string | *(无默认值)* | ✅ | bcrypt 哈希后的管理员密码。启动时种子数据写入 `auth.admin` 表 |

**生成 `ADMIN_PASSWORD_HASH` 的方法**：

```bash
# 方法一：使用 Python（推荐）
python -c "import bcrypt; print(bcrypt.hashpw(b'admin123', bcrypt.gensalt(rounds=12)).decode())"

# 方法二：使用 htpasswd（需安装 apache2-utils）
htpasswd -bnBC 12 "" admin123 | cut -d: -f2

# 方法三：使用 openssl（需配合 Python 哈希，不推荐直接使用）
```

> 开发环境建议密码 `admin123`；生产环境**必须**使用强密码（≥ 12 位）。

### 3.3 微信小程序

| 变量名 | 类型 | 默认值 | 必需 | 说明 |
|--------|:----:|:-----:|:----:|------|
| `WX_APPID` | string | *(无默认值)* | ✅ | 微信小程序的 AppID。在微信公众平台获取 |
| `WX_SECRET` | string | *(无默认值)* | ✅ | 微信小程序的 AppSecret。**严禁**提交到 Git |
| `WX_MOCK_MODE` | bool | `false` | ❌ | Mock 模式开关。设为 `true` 时跳过微信 API 调用，直接根据 `code` 生成 `mock_openid_{code}` 作为 openid，用于本地开发和调试 |

> **获取方式**：登录 [微信公众平台](https://mp.weixin.qq.com/) → 开发管理 → 开发设置 → AppID 和 AppSecret。
>
> **安全提示**：AppSecret 等同于密码，泄露后他人可获取用户 OpenID。生产环境建议使用微信云托管或密钥管理服务存储。

|--------|:----:|:-----:|:----:|------|

## 9. 常见问题

### Q1: 如何生成 `ADMIN_PASSWORD_HASH`？

```python
# 开发环境密码 admin123
import bcrypt
hashed = bcrypt.hashpw(b"admin123", bcrypt.gensalt(rounds=12))
print(hashed.decode())
# 输出示例: $2b$12$LJ3m4ys3Lk0TSwHnbfOMiOXPm1Q5eH7F0YxJ6n8Z1q2R3S4T5V6W
```

### Q2: `DATABASE_URL` 和 `REDIS_URL` 是否需要手动设置？

**不需要**。这两个 URL 由 `shared/config.py` 的 `get_database_url()` 和 `get_redis_url()` 函数自动组合。各服务的 `config.py` 调用这些函数生成最终的 URL。

### Q3: Docker Compose 环境和本地开发环境的 `.env` 可以共用吗？

**不建议**。`DB_HOST`、`REDIS_HOST`、`KNOWLEDGE_SERVICE_URL`、`UPLOAD_DIR` 四个变量的值不同。建议维护两个文件：

| 用途 | 文件名 | Gitignore |
|:----|--------|:---------:|
| Docker Compose | `.env` | ✅ |
| 本地开发 | `.env.local` | ✅ |

### Q4: `JWT_SECRET` 泄露了怎么办？

1. 立即更换 `JWT_SECRET` 为新的强随机字符串
2. 重启 Auth 和 Core 服务（所有已签发的 JWT 将立即失效）
3. 所有用户需要重新登录

### Q5: 为什么 `JWT_ALGORITHM` 固定为 HS256？

HS256（HMAC with SHA-256）是对称签名算法，使用单个 Secret 即可完成签发和验证。Auth 和 Core 共享同一个 Secret，无需公钥分发，适合微服务内部架构。如果将来需要支持第三方应用，可升级为 RS256（非对称算法）。
