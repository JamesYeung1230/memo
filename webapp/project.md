## 项目定位

Web 端管理后台是「码上启航」平台的运营管理后台，面向**运营者**，提供 AI 辅助的内容生产、知识内容全生命周期管理、运营策略灵活配置、用户笔记安全审核以及核心数据指标实时监控能力。

> **说明**：本项目为个人项目，单一管理员账号即拥有全部操作权限，不涉及多账号/多角色管理。

| 运行环境 | 微信小程序 | PC/Web 浏览器 |

## 非功能需求

### 性能要求

| 指标 | 要求 |
|------|------|
| 页面首屏加载 | ≤ 2s |
| 列表分页加载（100条） | ≤ 500ms |
| 卡片保存响应 | ≤ 1s |
| AI内容生成响应 | ≤ 10s（异步任务） |
| 数据看板图表渲染 | ≤ 2s |

### 安全要求

- 管理端登录需账号密码认证，密码加密存储（bcrypt）
- 登录态 Token 有效期 24 小时，过期需重新登录
- 敏感操作（删除领域/章节/卡片）需二次确认 + 输入验证
- 所有删除类操作记录操作日志，可追溯到人
- XSS 防护：富文本输入需做安全过滤
- AI审核内容需脱敏处理后发送至审核服务

### 兼容性

- 支持 Chrome 90+、Edge 90+、Firefox 88+
- 推荐分辨率 1920×1080，最低兼容 1366×768
- 不支持移动端浏览器（管理后台为 PC Web 端专用）

### 用户体验

- 所有列表支持分页、搜索、排序
- 表单操作有即时校验反馈
- 删除等危险操作有三层确认：弹窗确认 → 输入验证 → 结果反馈
- 操作成功后 Toast 提示，失败后展示错误原因
- AI生成内容支持流式展示（逐字段生成）

## 数据初始化方案

v1.0 的知识内容（领域、章节、卡片、题目）、成就徽章、运营配置的初始数据，采用 **AI 工作流辅助生成 + 人工审核** 的方式完成。

| 步骤 | 内容 | 执行方式 |
|:---:|------|---------|
| 1 | 知识领域与章节结构 | AI 生成 JSON 种子数据，人工审核后执行数据库脚本导入 |
| 2 | 知识卡片内容 | AI 逐领域生成卡片内容，人工逐条审核后导入 |
| 3 | 题目 | AI 根据卡片生成单选题，人工审核后导入 |
| 4 | 成就徽章 | AI 建议徽章方案，人工确认后通过管理后台录入 |
| 5 | 运营默认配置 | AI 生成推荐配置参数，人工确认后录入 |

> 上线后的增量内容通过 Web 管理端直接操作，不再依赖 AI 工作流。生成脚本和种子数据纳入版本管理（存放于 `backend/seeds/`）。

## 强制要求

### 1. 上下文加载
每次执行任务前，**必须先加载以下文件**到上下文中：

1. **[project.md](project.md)** — 项目总览、当前阶段和核心原则
2. **[docs/技术可行性分析报告.md](docs/技术可行性分析报告.md)** — 技术选型决策与架构设计
3. **[docs/前端技术开发指导及规范.md](docs/前端技术开发指导及规范.md)** — 前端开发详细规范指南
4. **[../CLAUDE.md](../CLAUDE.md)** — 项目级 Claude Code 开发规范

### 2. 意图确认
收到任务后，**仔细分析用户意图**。如果存在以下情况，必须**反问用户确认**后再执行：
- 需求描述模糊，存在多种理解方式
- 与现有产品逻辑可能存在冲突
- 技术方案存在多种可选路径
- 任务的边界范围不清晰

### 3. Agent 协同
执行任务时，在可用的 Agent 配置中选取合适的 Agent。当任务可以拆分为多个独立子任务时，**协同调用多个 Agent 并行工作**，提升任务效率。

可用 Agent：
- `frontend-architect` — 前端开发、UI 实现
- `ui-designer` — 交互设计、视觉还原
- `backend-architect` — 后端 API 设计
- `search` — 代码搜索与调研

### 4. Git 本地提交
**每次修改完成后必须维护 git 仓库**，将代码修改记录提交到本地仓库。提交信息需清晰描述本次变更内容。

### 5. 禁止擅自推送远程
**用户未主动要求，不得擅自提交到远程仓库。** 所有 git 操作仅限于本地仓库。

### 6. README 维护
在工作目录维护 [README.md](README.md)，说明该目录下项目内容的情况。项目结构或功能有变更时同步更新。

### 7. 文件修改边界
**所有 Agent 以及所有修改操作，只能修改当前项目文件夹 `d:\workspace\memo\webapp\` 下的文件，不能修改本项目文件夹外的其他文件。**

## 核心原则：纯前端项目

这是一个**纯粹的前端项目**（Web 管理后台），不包含后端服务。

### 后端调用规范

在遇到需要调用后端接口的场景时：
1. **严格依照后端 SDK 文档**进行调用
2. 如果发现后端 SDK 文档与后端实际提供的 SDK **不一致**：
   - **坚持以文档为准**
   - **不得**直接使用后端 SDK 中提供的不符合规范的 SDK
   - 将问题原因报告为**后端问题**，由后端团队修正
3. **不要**强行改变前端业务逻辑来适配后端的错误实现

### 设计还原规范

1. 所有 UI 实现严格参照 [docs/PRD.md](docs/PRD.md) 中的功能设计要求
2. 设计 Token（颜色、圆角、阴影、字体）统一使用小程序 PRD §5.4 定义的值
3. 品牌默认色 `#160C57` 深紫色为视觉还原的基准
