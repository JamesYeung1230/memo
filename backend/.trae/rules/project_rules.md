# 卡片学记 后端服务 — AI 编程注意事项

> 本文件是对 [project.md](../../project.md) 中「强制要求」的补充，聚焦 AI Agent 在执行后端开发任务时的行为约束。
> 技术栈、API 设计等具体规范以 `project.md` 为准。

---

## 一、上下文感知

- Agent 在修改任何文件前，必须先使用 SearchCodebase 或相关搜索工具获取项目上下文
- 了解项目中已有的工具函数、中间件、模型、路由后再进行编码，避免重复造轮子
- 修改代码前，先阅读相邻文件和依赖文件，理解现有代码风格和约定
- 每次任务开始前必须加载以下锚点文档：
  1. [project.md](../../project.md) — 项目背景、当前阶段、技术栈
  2. [本文件](project_rules.md) — AI 编程行为约束

## 二、修改验证

- 每次修改完成后，必须运行对应的 lint/typecheck 命令进行验证（如 `ruff`、`mypy`、`eslint` 等）
- 修改涉及的功能应运行相关测试确认不破坏已有逻辑
- 多步骤任务中，每完成一步都应验证后再继续下一步
- API 接口修改后应通过 API 测试工具（如 `api-test-pro` Agent）验证接口正确性

## 三、依赖管理

- 禁止引入项目未使用的新依赖（pip 包、npm 包等），除非用户明确要求
- 使用新依赖前，先检查 `requirements.txt`、`Pipfile`、`pyproject.toml` 或 `package.json` 等文件中是否已有替代方案
- 不得使用过时、废弃或不安全的库版本
- 引入新依赖时必须评估其对项目体积、安全性和兼容性的影响

## 四、安全红线

- 禁止在代码中硬编码任何密钥、Token、密码或敏感信息（数据库密码、JWT Secret、API Key 等必须使用环境变量）
- 禁止生成存在 SQL 注入、XSS、CSRF、SSRF 等安全漏洞的代码
- 涉及认证、鉴权、支付等敏感功能时，必须使用安全的实现方式
- API 接口必须有输入校验和权限控制
- 用户密码必须加密存储（如 bcrypt），禁止明文存储

## 五、文件创建约束

- 禁止生成文档类 `.md` 文件（README、CHANGELOG 等），除非用户明确要求
- 优先修改已有文件，而非创建新文件
- 除非绝对必要，否则不要创建新文件

## 六、测试覆盖

- 每个 API 接口或功能完成后，必须编写或更新对应的测试用例
- 测试应覆盖正常路径、边界条件和异常场景
- 遵循项目已有的测试框架和规范
- Bug 修复必须先编写复现测试，确认测试失败后再修复

## 七、数据库与数据安全

- 数据库迁移脚本必须可回滚（提供 `up` / `down` 双向操作）
- 禁止直接在生产环境执行危险操作（如 `DROP TABLE`）
- 批量操作必须考虑事务保护和数据一致性

## 八、AI Agent 协同

- 后端开发涉及以下场景时可调用对应 Agent 并行工作：
  - `backend-architect` — API 设计、服务端架构
  - `api-test-pro` — API 测试、性能测试、契约测试
  - `performance-expert` — 性能分析、瓶颈定位
  - `devops-architect` — CI/CD 配置、部署自动化
  - `search` — 代码搜索与调研

## 九、任务追踪

- 复杂多步骤任务必须使用 TodoWrite 工具创建任务列表并跟踪进度
- 确保长链任务不丢失上下文，每一步都清晰可追踪

## 十、不确定时确认

- 遇到不确定的技术选型、架构决策或需求分歧时，使用 AskUserQuestion 与用户确认
- 不要在不确定的情况下「猜」一个方案直接执行
- 当任务描述模糊时，主动向用户澄清具体需求
