## 一、产品概述

### 1.1 产品名称

**码上启航**（CodeSail）

> 备选名称：`AI编程第一课` | `开发口袋` | `编程启蒙师`

### 1.2 产品定位

**一款面向非专业编程用户的小程序工具**，通过碎片化、轻量化的知识卡片与刷题练习，帮助AI编程学习者快速建立计算机基础认知和软件开发基本概念，使其能够更高效地驾驭AI工具完成软件开发任务。

### 1.3 一句话描述

用最简单的方式，让非开发者掌握编程基础知识，从而更好地用AI写代码。

### 1.4 目标用户

| 用户画像 | 特征描述 | 核心诉求 |
|---------|---------|---------|
| 产品经理 | 需与技术团队沟通，偶尔用AI生成原型 | 理解技术术语、看懂技术方案、能向AI准确描述需求 |
| 市场营销/运营人员 | 需搭建落地页、处理数据报表 | 理解前端基础、会简单脚本、能用AI写数据处理代码 |
| 非软件类技术人员 | 如硬件工程师、数据分析师等 | 补充软件工程知识、理解开发流程 |
| 传统开发人员 | 如前端/后端工程师，有编码能力但未接触AI编程 | 了解AI编程与传统编程的差异、掌握AI编程工具链、学会将AI融入现有开发工作流 |
| AI编程爱好者 | 无编程背景但想通过AI做应用 | 系统补齐基础知识、学会正确引导AI的方法 |

### 1.5 用户痛点

1. **知识鸿沟**：想用AI编程但连"什么是API""什么是数据库"都不清楚，无法精准描述需求
2. **学习门槛**：传统编程教程太深太广，非开发者没有时间从零学起
3. **知识遗忘**：零散学习容易忘，缺乏系统性的复习和巩固机制
4. **动力不足**：学习过程枯燥，缺乏成就感和正向激励

### 1.6 产品核心价值

```
                    学习 → 掌握 → 应用
                    ┌──────────────┐
    知识卡片/刷题    │   记忆强化     │   AI编程实践
    （入门输入）     │ （巩固内化）   │  （场景输出）
                    └──────────────┘
                    积分体系贯穿全程
```

## 二、核心功能

### 2.1 笔记管理

#### 2.1.1 功能概述

用户在使用小程序过程中可记录和管理个人笔记，支持自由笔记和关联笔记两种模式。笔记可选择提交审核，审核通过后可在平台内分享与转发。

#### 2.1.2 功能详情

| 功能点 | 描述 |
|-------|------|
| **自由笔记** | 用户可在笔记模块中独立创建、编辑、删除笔记，支持纯文本格式；笔记按时间倒序排列，支持搜索和标签分类 |
| **关联笔记** | 在浏览知识卡片或做题过程中，用户可一键关联当前知识点创建笔记，笔记自动标记来源知识内容 |
| **笔记列表** | 展示用户所有笔记，支持按时间、标签筛选，支持关键字搜索 |
| **笔记编辑** | 支持文本输入，单篇笔记字数上限5000字；支持插入知识卡片的快捷引用链接 |
| **笔记删除** | 支持单条删除和批量删除，删除前需二次确认 |
| **笔记审核提交** | 用户可主动将笔记「提交审核」，提交后笔记内容上传至服务端进入审核队列 |
| **笔记分享** | 用户可将笔记分享转发给微信好友或生成分享卡片；分享前触发内容审核流程；未通过审核的笔记仅自己可见，不可分享 |
| **审核状态** | 每条笔记有审核状态标记：未提交 / 审核中 / 已通过 / 已驳回；驳回时附带驳回原因 |

#### 2.1.3 业务规则

- **本地隐私默认**：用户创建的笔记默认仅在本地存储，不上传服务端，卸载小程序后数据丢失
- **风险告知**：用户首次进入笔记功能时，弹窗明确提示：「笔记数据仅存储于本地，卸载小程序后数据不可恢复，请谨慎操作」，用户点击「已知晓」后方可使用笔记功能
- **提交审核触发上传**：用户点击「提交审核」后，笔记内容上传服务端，进入审核队列
- **审核机制**：笔记发布/分享时自动触发三级审核流程（详见 §2.1.4）
- **审核时效**：机器审核实时返回结果，人工复核最长24小时内完成
- **审核不通过处理**：笔记保留在本地，用户可修改后重新提交，不限制重新提交次数
- **分享权限**：仅审核状态为「通过」的笔记可被分享转发；审核未通过或审核中的笔记仅作者本人可见
- **分享限制**：审核中或已驳回的笔记，「分享」按钮置灰不可用
- **分享内容规范**：笔记分享卡片展示标题（截取前20字）、摘要（截取前50字）、关联知识标签、分享者昵称；不展示完整内容，引导好友进入小程序查看
- **撤回审核**：审核中的笔记可撤回，撤回后恢复为「未提交」状态
- **笔记违规处理**：若笔记内容违规（含敏感词、广告、不当言论等），审核驳回且标记用户，累计3次违规将限制该用户的笔记提审功能7天
- **分享违规处理**：连续3次审核驳回的用户，笔记分享功能临时冻结7天
- 单用户笔记数量上限：500条
- 关联笔记在来源知识内容被移除时，保留笔记但去除关联链接

#### 2.1.4 笔记审核流程

当用户提交笔记（含创建公开笔记或发起分享操作）时，系统启动三级审核流程：

```
用户提交笔记/发起分享
       │
       ▼
┌──────────────────┐
│  第一级：敏感词过滤  │ ── 命中 ──→ 自动驳回，提示修改
└──────────────────┘
       │ 未命中
       ▼
┌──────────────────┐
│  第二级：AI内容审查  │ ── 高风险 ──→ 自动驳回
└──────────────────┘
       │ 中风险
       ▼
┌──────────────────┐
│ 第三级：人工复核队列  │
└──────────────────┘
       │
   ┌───┴───┐
   ▼       ▼
 通过    驳回（附原因）
   │       │
   ▼       ▼
可分享   仅自己可见
```

**第一级：敏感词过滤（自动实时）**

| 项目 | 说明 |
|------|------|
| 触发时机 | 用户点击「发布」或「分享」时 |
| 过滤范围 | 笔记标题 + 正文全文 |
| 匹配规则 | 精确匹配 + 拼音匹配 + 谐音匹配 |
| 命中结果 | 标记为「自动驳回」，前端 Toast 提示「内容包含敏感信息，请修改后重试」 |
| 用户体验 | 驳回后不保存当前版本，用户修改后可重新提交 |

**第二级：AI内容审查（自动异步）**

| 项目 | 说明 |
|------|------|
| 触发时机 | 敏感词过滤通过后，调用AI审查接口 |
| 审查维度 | 违规广告、色情低俗、暴力谩骂、政治敏感、虚假信息 |
| 返回结果 | 通过（低风险）/ 人工复核（中风险）/ 驳回（高风险） |
| 低风险 | 直接标记为「审核通过」，笔记可正常分享 |
| 中风险 | 进入人工复核队列，笔记状态为「审核中」，暂时不可分享 |
| 高风险 | 自动驳回，笔记仅自己可见，提示「内容不符合社区规范」 |
| 异步体验 | AI审查期间笔记可正常保存和编辑，分享按钮置灰并显示「审核中」 |

**第三级：人工复核（运营人员在Web管理端操作）**

| 项目 | 说明 |
|------|------|
| 复核对象 | AI标记为中风险的笔记 |
| 操作选项 | 通过 / 驳回（需填写驳回原因） |
| 通过后 | 笔记状态变为「审核通过」，分享功能恢复 |
| 驳回后 | 笔记状态变为「审核驳回」，展示驳回原因给用户，仅自己可见 |
| 用户申诉 | 驳回后用户可修改笔记内容重新提交审核 |

**笔记状态流转**：

| 状态 | 含义 | 用户可见 | 可分享 |
|------|------|:------:|:------:|
| 草稿 | 用户保存但未提交审核 | ✓ | ✗ |
| 审核中 | AI审查中或人工复核队列中 | ✓ | ✗ |
| 审核通过 | 审查通过 | ✓ | ✓ |
| 审核驳回 | 敏感词命中 / AI驳回 / 人工驳回 | ✓ | ✗ |

**业务规则**：
- 笔记的「编辑」操作不触发审核，仅「保存为草稿」
- 用户在笔记详情页点击「提交分享」才触发审核流程
- 已通过的笔记若被编辑，分享状态重置，需重新提交审核
- 敏感词库由Web管理端维护（详见Web端PRD改动）

### 2.2 知识学习

#### 2.2.1 知识内容体系

v1.0 阶段涵盖七大知识领域，以「章节-小节-知识点」三级结构组织：

| 编号 | 知识领域 | 示例知识点 | 知识卡片数量（预估） |
|------|---------|-----------|-------------------|
| K01 | 编程基础概念 | 变量、函数、条件判断、循环、数据类型 | 10~15 |
| K02 | 计算机网络基础 | HTTP/HTTPS、域名与IP、前端与后端、API概念 | 8~12 |
| K03 | 软件工程流程 | 需求分析→设计→开发→测试→部署 | 8~10 |
| K04 | 数据库基础 | 什么是数据库、表与字段、增删改查（CRUD） | 6~10 |
| K05 | 操作系统基础 | 文件系统、进程与线程、环境变量 | 5~8 |
| K06 | AI编程实践技巧 | 提示词结构、需求描述方法、错误排查思路 | 8~12 |
| K07 | AI编程与传统编程 | AI编程vs传统编程差异、AI编程工具链（Cursor/Copilot/Claude等）、从传统开发过渡到AI开发的思维转变、AI编程的优势与局限 | 10~14 |

#### 2.2.2 知识卡片学习（主学习路径）

| 功能点 | 描述 |
|-------|------|
| **卡片浏览** | 每张知识卡片包含：标题、核心概念（一句话）、详细说明（2~3段）、类比生活场景、关键词标签 |
| **目录导航** | 展示知识领域→章节→知识点的树形结构，显示学习进度百分比 |
| **卡片交互** | 左右滑动切换卡片，点击展开详细说明；卡片底部有「懂了」和「收藏」操作按钮 |
| **学习状态** | 每个知识卡片有「未学」「学习中」「已掌握」三种状态；点击「懂了」即标记为已掌握 |
| **收藏夹** | 用户可收藏知识卡片，在个人中心快速访问 |
#### 2.2.3 刷题学习（巩固学习路径）

| 功能点 | 描述 |
|-------|------|
| **题型** | v1.0仅支持单选题，每题4个选项 |
| **组题逻辑** | 按知识领域出题；先出已学知识点的题目，穿插少量未学题目激发学习兴趣 |
| **答题体验** | 选择答案后立即显示正确/错误和解析；解析中用高亮标注对应知识卡片的核心概念 |
| **错题本** | 自动收集错题，支持按时间/知识领域筛选，支持错题重练 |
| **进度统计** | 展示各领域答题正确率和已掌握知识点数量 |
| **每日挑战** | 每天推送3~5道题，连续打卡有积分加成 |

### 2.3 记忆强化

#### 2.3.1 功能概述

基于间隔重复（艾宾浩斯遗忘曲线）原理，结合笔记回顾和错题重练，构建多维度的知识巩固体系。用户可自行配置复习节奏，灵活适配不同学习习惯和记忆能力。

#### 2.3.2 机制说明

| 机制 | 触发方式 | 频率规则 |
|------|---------|---------|
| **间隔复习推送** | 系统根据用户自定义的复习节点，在设定的遗忘临界点推送复习提醒（卡片回顾+答题） | 用户自行配置复习节点（默认：学习后第1/2/4/7/15天） |
| **错题再练** | 错题自动进入再练队列，安排在次日重练 | 答对2次后移出再练队列 |
| **笔记回顾** | 用户收藏/关联的笔记随机推送回顾 | 每日最多推送3条 |
| **遗忘预警** | 用户超过自定义预警天数未复习的知识点，进入预警列表 | 用户自行配置预警天数（默认7天） |

#### 2.3.3 复习计划配置

用户可在「记忆强化设置」页面自定义以下参数：

| 配置项 | 说明 | 默认值 | 可配置范围 |
|-------|------|--------|-----------|
| **复习节点** | 学习后第N天触发复习提醒 | [1, 2, 4, 7, 15] | 1~5个节点，每节点1~60天 |
| **每日复习上限** | 每日最多推送复习卡片数 | 20张 | 5~50张 |
| **遗忘预警天数** | 连续未复习多少天触发预警 | 7天 | 3~30天 |
| **复习提醒时间** | 每日微信服务通知推送时段 | 20:00 | 08:00~22:00 |
| **周末免打扰** | 周六/周日是否暂停复习推送 | 否 | 开/关 |
| **恢复默认** | 一键恢复系统推荐配置 | — | — |

> **交互规则**：
> - 初次使用时，系统默认使用标准艾宾浩斯节点（1/2/4/7/15天）
> - 修改配置后，仅对新学习的知识点生效，已排入复习计划的不受影响
> - 系统提供「推荐配置」「轻松配置（低频）」「强化配置（高频）」三档预设，一键切换
> - 配置页展示当日待复习数量预览，方便用户感知调整效果

### 2.4 学习积分制

#### 2.4.1 积分体系设计

积分获取严格遵循「按难度分配」原则，降低简单重复行为的收益，引导用户投入高质量学习行为或通过广告获取积分。

| 行为 | 获得积分 | 每日上限 | 难度等级 |
|------|---------|---------|---------|
| 学习1张知识卡片（点「懂了」） | +1 | 10 | ⭐ 低——碎片化积累 |
| 完成每日挑战（3~5题全对） | +15 | 15 | ⭐⭐⭐ 高——需全部答对方可获得 |
| 连续打卡第3天 | +15 | — | ⭐⭐ 中——里程碑奖励 |
| 连续打卡第7天 | +30 | — | ⭐⭐⭐ 高——周里程碑 |
| 连续打卡第14天 | +60 | — | ⭐⭐⭐ 高——双周里程碑 |
| 创建1条笔记（字数≥20字） | +5 | 15 | ⭐⭐ 中——需有实质内容 |
| 观看激励广告（完整观看） | +10 | 100 | ⭐ 低——核心盈利通道 |

> **设计原则**：
> - 单纯浏览卡片或刷题不直接给积分，必须点「懂了」或完成挑战才算有效学习行为
> - 每日挑战必须全部答对才发放积分，未全对不扣次数但无积分
> - 笔记需≥20字有效内容，短笔记不触发积分
> - 激励广告必须完整观看（不可中途关闭），未完整观看不发放积分

#### 2.4.2 积分用途

| 用途 | 消耗积分 | 说明 |
|------|---------|------|
| 解锁新知识领域 | 30~60 | 免费解锁K01~K03，K04~K07需消耗积分解锁 |
| 解锁高级知识卡片 | 20 | 部分进阶知识点需要积分兑换 |
| 兑换虚拟成就徽章 | 30~200 | 在个人中心展示，纯荣誉性质 |

#### 2.4.3 积分规则

- 积分不可转赠、不可提现
- 积分永久有效，不会过期
- 用户卸载后积分数据丢失（v1.0无云端同步）

### 2.5 首页个性化配置

#### 2.5.1 功能概述

用户可对首页进行个性化定制，包括首页模块的显示/隐藏与排序、跟随全局主题色自动适配界面风格。运营推送的Banner轮播同步展示，不可关闭但可收起。

#### 2.5.2 Banner展示

| 功能点 | 描述 |
|-------|------|
| 轮播展示 | 首页顶部Banner轮播区，最多展示5张，3秒自动轮播；固定比例 750×300px（适配小程序标准Banner规格）；支持JPG/PNG/WebP/GIF格式 |
| 点击跳转 | 点击Banner跳转配置的小程序内页面（知识卡片/答题/积分商店等） |
| 关闭/收起 | 用户可手动收起Banner区（收为一条窄条），下次冷启动自动展开 |
| 有效期 | Banner仅在运营配置的有效期内展示 |
| 兜底策略 | 无Banner时自动隐藏轮播区；仅1张Banner时不轮播 |

#### 2.5.3 主题色应用

| 功能点 | 描述 |
|-------|------|
| 全局跟随 | 小程序全局自动应用管理端配置的当前主题色 |
| 生效范围 | 导航栏、TabBar选中态、按钮、强调文字、进度条、图标高亮等 |
| 预设色板 | 运营端配置的主题色通过接口下发，客户端实时生效（无需重启） |
| 默认主题色 | 品牌主色（科技蓝 #4A90D9） |

#### 2.5.4 首页模块排序

| 功能点 | 描述 |
|-------|------|

## 三、盈利模式

### 3.1 广告策略

| 广告类型 | 展示场景 | 频率 | 用户选择权 |
|---------|---------|------|-----------|
| **开屏广告** | 小程序启动时展示 | 每次冷启动 | 3~5秒后可跳过 |
| **激励广告** | 用户主动点击「看广告赚积分」 | 用户自主触发 | 完全自愿，单次观看约15~30秒 |
| **插屏广告** | 暂不接入 v1.0 | — | — |

### 3.2 积分与广告的盈利闭环

```
        用户观看激励广告（完整观看）
              │
              ▼
         获得积分奖励（+10/次）
              │
              ▼
        积分解锁新知识（K04~K07）
              │
              ▼
         学习更多内容
              │
              ▼
        积分稀缺→看广告成最稳定来源→盈利闭环
```

## 五、非功能需求

### 5.1 性能要求

| 指标 | 要求 |
|------|------|
| 小程序冷启动时间 | ≤ 2秒 |
| 页面切换响应 | ≤ 500ms |
| 知识卡片加载 | ≤ 1秒（预加载机制） |
| 接口响应时间 | ≤ 500ms（P99） |

### 5.2 兼容性

- 微信小程序基础库版本 ≥ 2.10.0
- 支持 iOS 12.0+ / Android 8.0+
- 适配 iPhone SE ~ Pro Max 系列屏幕尺寸

### 5.3 数据安全

- 用户笔记数据默认存储于微信小程序本地Storage，仅在用户主动提交审核时上传至服务端
- 提审笔记在审核通过后可被其他用户查看（分享内容），用户应在提审前自行确认内容不包含隐私信息
- 学习进度数据本地存储，定期同步至服务端（若后续版本加入账号体系）
- 不采集用户敏感个人信息
- 用户配置（主题色、字体、复习设置）本地缓存 + 服务端双写，确保多端一致（后续版本）

### 5.4 用户体验

- 知识卡片文本以通俗易懂为第一原则，避免堆砌专业术语
- 所有操作提供即时反馈（按钮态、加载态、完成态）

## 八、验收标准

### 8.1 总体验收条件

1. 用户可流畅浏览至少7个知识领域的全部知识卡片
2. 用户可完成刷题并查看答案解析
3. 用户可创建、编辑、删除笔记，并可提交审核、查看审核状态、分享已通过笔记
4. 系统能够按用户自定义的间隔重复规则推送复习提醒
5. 积分获取和消耗逻辑准确无误
6. 运营Banner可正常配置、轮播及跳转
7. 主题色跟随管理端配置全局生效；用户可切换字体大小
8. 开屏广告和激励广告正常展示
9. 核心页面在主流机型上无卡顿、无布局错乱

### 8.2 各模块验收要点

| 模块 | 核心验收点 |
|------|-----------|
| 笔记管理 | 创建>编辑>删除闭环完整；关联笔记正确跳转知识卡片；搜索和筛选结果准确；提审→审核中→通过/驳回状态流转正确；已通过笔记可正常分享、审核中/驳回笔记分享按钮置灰；驳回附带原因且可修改重新提交；违规累计3次限制提审7天 |
| 知识卡片 | 目录树层级正确；卡片内容完整；左右滑动切换流畅；学习状态标记正确 |
| 刷题学习 | 题目答案判定正确；解析展示对应知识卡片链接；错题本自动收录准确；每日挑战题目不重复 |
| 记忆强化 | 复习推送时机符合用户自定义节点；配置修改对已有复习计划无影响；三档预设一键切换有效；错题答对2次后正确移出；笔记回顾每日不超3条 |
| 积分体系 | 各行为积分加减准确（含难度等级校验）；每日上限生效；挑战未全对不发放积分；笔记不足20字不触发积分；解锁消耗后知识内容立即可访问 |
| 页面装饰 | Banner按配置正确轮播和跳转；跳转目标准确（知识卡片/积分中心等）；无Banner时轮播区自动隐藏；主题色跟随管理端配置全站生效；字体大小切换全局生效 |
| 广告系统 | 开屏广告倒计时后正确跳过；激励广告完整观看后积分正确到账；广告未完整观看不发放积分 |

## 九、风险与应对

| 风险 | 影响 | 应对策略 |
|------|------|---------|
| 知识内容质量不高 | 用户流失 | 邀请专业开发者审校内容；收集用户反馈持续优化 |
| 用户学习动力持续性不足 | 留存率低 | 强化积分激励和每日挑战；增加成就感和社交分享 |
| 广告收入不足以覆盖成本 | 商业模式不成立 | 预留会员订阅方案作为备选；控制内容生产成本 |
| 微信小程序审核风险（涉教育类） | 发布受阻 | 确保不涉及学位教育、职业资格培训等需资质领域 |
