# 码上启航 微信小程序 — AI 编程注意事项

> 本文件是对 [project.md](../../project.md) 中「强制要求」的补充，聚焦 AI Agent 在执行小程序前端开发任务时的行为约束。
> 技术栈、UI 规范等具体规范以 `project.md` 为准。

---

## 一、上下文感知

- Agent 在修改任何文件前，必须先使用 SearchCodebase 或相关搜索工具获取项目上下文
- 了解项目中已有的组件、工具函数、页面结构后再进行编码，避免重复造轮子
- 修改代码前，先阅读相邻文件和依赖文件，理解现有代码风格和约定
- 每次任务开始前必须加载以下锚点文档：
  1. [project.md](../../project.md) — 项目背景、当前阶段、技术栈
  2. [本文件](project_rules.md) — AI 编程行为约束

## 二、修改验证

- 每次修改完成后，必须运行对应的 lint 命令进行验证（如 `eslint` 等）
- 修改涉及的功能应在微信开发者工具中验证 UI 还原度和交互正确性
- 多步骤任务中，每完成一步都应验证后再继续下一步
- WXML/WXSS 修改后应确保页面布局在不同屏幕尺寸下正常显示

## 三、依赖管理

- 禁止引入项目未使用的新依赖（npm 包、插件等），除非用户明确要求
- 使用新依赖前，先检查 `package.json`、`project.config.json` 等文件中是否已有替代方案
- 不得使用过时、废弃或不安全的库版本
- 微信小程序插件需确认与目标基础库版本的兼容性

## 四、安全红线

- 禁止在代码中硬编码任何密钥、Token、密码或敏感信息
- 禁止在小程序端存储用户密码等敏感信息
- 涉及用户数据操作时，必须遵循最小数据原则，仅请求必要权限
- 网络请求必须使用 HTTPS，禁止明文 HTTP 请求
- 用户输入必须做安全过滤，防止 XSS 攻击

## 五、文件创建约束

- 禁止生成文档类 `.md` 文件（README、CHANGELOG 等），除非用户明确要求
- 优先修改已有文件，而非创建新文件
- 除非绝对必要，否则不要创建新文件

## 六、测试覆盖

- 每个功能完成后，必须编写对应的测试用例或测试指引
- 测试应覆盖正常路径、边界条件和异常场景
- 交互行为测试应涵盖不同机型屏幕适配

## 七、UI 还原与交互

- 所有 UI 实现严格参照交互设计文档和 PRD 中的设计规范
- 主题色、圆角、字体等设计 Token 以设计规范定义值为准，禁止硬编码色值
- 页面交互状态（加载中、空数据、错误、正常）必须完整覆盖
- 微信小程序原生 API 调用需做好兼容处理（基础库版本判断）

## 八、AI Agent 协同

- 前端开发涉及以下场景时可调用对应 Agent 并行工作：
  - `frontend-architect` — 前端开发、UI 实现
  - `ui-designer` — 交互设计、视觉还原
  - `backend-architect` — 后端 API 设计理解
  - `search` — 代码搜索与调研

## 九、任务追踪

- 复杂多步骤任务必须使用 TodoWrite 工具创建任务列表并跟踪进度
- 确保长链任务不丢失上下文，每一步都清晰可追踪

## 十、不确定时确认

- 遇到不确定的技术选型、架构决策或需求分歧时，使用 AskUserQuestion 与用户确认
- 不要在不确定的情况下「猜」一个方案直接执行
- 当任务描述模糊时，主动向用户澄清具体需求
